# БУР — передача проєкту

Документ для того, хто продовжує роботу (людини або агента). Тут: що це,
у якому воно стані, які рішення прийняті й чому, і що робити далі.

---

## 1. Що це

Сайт подобової оренди будівельного інструменту (Київ, Харків, Львів). Зроблений
за дизайн-хендофом `design_handoff_bur_rental` — 20 екранів, які були
HTML-прототипами і перенесені в Laravel.

**Ключова бізнес-ідея, від якої залежать усі технічні рішення:** сайт показує
**реальну наявність по датах і філіях**. Конкуренти цього не роблять — у них
«залиште заявку, ми уточнимо». Тому все, що стосується наявності, мусить бути
правдивим і швидким; це не другорядна деталь, а сам продукт.

Стек: **PHP 8.4 · Laravel 13 · Filament 5 · Blade + Tailwind v4 + Alpine.js**.
БД: SQLite для розробки, MySQL на хостингу.

## 2. Де код і як запустити

Код: гілка **`claude/service-deployment-fvcr4g`** репозиторію
`kristinadeneshchuk/catering-crm`, підпапка **`bur-rental/`**.

> Проєкт живе в чужому репозиторії тимчасово — планувався переїзд у
> `horenkotaras-sudo/bur`, але не завершився. Історія вже вирізана в чисту
> гілку `bur-rental-main` (5 комітів, застосунок у корені) — якщо переїзд
> потрібен, беріть її.

```bash
composer install
npm install
cp .env.example .env && php artisan key:generate
touch database/database.sqlite
php artisan migrate:fresh --seed
npm run build
php artisan serve
```

Тести: `php artisan test` — **51 тест, усі зелені**. Стиль: `./vendor/bin/pint`.
Адмінка: `/admin`, доступи з `.env` (`ADMIN_EMAIL` / `ADMIN_PASSWORD`).

## 4. Інваріанти — те, що легко зламати

Це найважливіший розділ. Кожен пункт — наслідок реальної помилки або свідомого
рішення; порушення кожного дає баг, який не видно одразу.

**Наявність рахується поштучно.** `inventory.qty` — скільки одиниць на полиці,
`unavailable_dates.qty` — скільки зайнято в конкретний день. Позиція стає
недоступною, лише коли зайняті **всі** екземпляри. Кожен рядок зайнятості
прив'язаний до `booking_id` — без цього дострокова здача однієї броні звільнить
чужі дати. Уся логіка в `App\Services\Availability`, обходити її не можна.

**Дати зберігаються рівно як `Y-m-d`.** У `UnavailableDate` є мутатор, який
зрізає час. Без нього Eloquent пише «2026-08-14 00:00:00», `firstOrCreate` не
знаходить наявний рядок, вставляє дубль і падає на унікальному індексі — тобто
бронювання на вже зайняту дату віддає 500. Був такий баг, є тест.

**Резервування — тільки через `Availability::reserve()`.** Він блокує рядок
`inventory` (`lockForUpdate`) усередині транзакції, перевіряє наявність і аж тоді
займає дати. Викликати `hold()` напряму з контролера не можна: два запити на
останній екземпляр устигали обидва побачити «вільно» і зайнятість переповзала за
склад. Є тест `test_booking_beyond_stock_never_holds_more_units_than_the_shelf_has`.

**`products.search_text` збирається подією `saving`.** Якщо міняєте товари в
обхід моделі (прямий `DB::table()->update()`, імпорт, перейменування бренду чи
категорії) — після цього `php artisan search:reindex`, інакше товар шукатиметься
за старими даними.

**Ціни рахує тільки сервер.** `App\Services\RentalPricing` бере тариф із бази за
фактичним строком. Ціна, надіслана браузером, ігнорується повністю. Є тест
`test_client_supplied_prices_are_ignored` — не послаблюйте його.

**Тарифна сходинка — три рівні на товар** (`tariff_tiers`): 1–2 дні базовий,
від 3 днів −17%, від 7 днів −31%. Прострочення рахується за **базовим** тарифом:
знижка за строк на прострочення не діє.

**Глобальний scope `published`.** Вітрина бачить лише опубліковані товари;
імпортовані з чужого каталогу приходять чернетками. Адмінка знімає scope через
`withoutGlobalScope('published')` — якщо додаєте новий адмінський запит по
товарах, не забудьте це.

**`route:cache` не працює.** У `routes/web.php` є closure-роути, Laravel їх не
серіалізує. `php artisan optimize` теж упаде. Якщо переведете ці роути на
контролери — можна вмикати.

**`env()` тільки в `config/`.** Після `config:cache` він повертає `null` в решті
коду. Одного разу це вже зламало назву в адмінці.

**Іконки сайту — `<x-ui-icon>`, не `<x-icon>`.** Filament притягнув blade-icons,
чий власний `x-icon` перебиває наш компонент.

**Місто — наскрізний контекст.** `ResolveCity` резолвить його раз на запит із
маршруту або сесії. Від нього залежать телефон у хедері, філії й доставка.
Сторінки помилок рендеряться повз middleware — там місто підставляє
view-composer у `ViewServiceProvider`.

**Дизайн-система: три радіуси, жодних тіней.** `2px` чипси, `6px` кнопки й поля,
`12px` картки (плюс `32px` — тільки pill нижньої навігації). Рівні поверхонь
передаються бордером і фоном; єдина дозволена тінь — `--shadow-float` для
плаваючих шарів. Усі токени в `@theme` у `resources/css/app.css`, hex у розмітці
бути не повинно.

## 5. Що робити далі — за пріоритетом

### 5.1. Залити на тестовий хост `bur.new.hor-hosting.top` ← поточне завдання

Пакет зібраний, лежить у двох архівах (`bur-app.zip` + `bur-vendor.zip`,
розпакувати в одну папку → вийде `bur_app`). Доступи до хостингу — окремим
файлом, у репозиторій їх не кладемо.

1. Залити `bur_app` у домашню директорію хостингу (поруч із папкою сайту).
2. Корінь сайту домену → `bur_app/public`. Якщо панель не дозволяє —
   `deploy/shared-hosting/index-alt.php` перейменувати в `index.php` і покласти
   в `public_html` разом із вмістом `bur_app/public/`.
3. Відкрити `https://домен/setup.php?token=<SETUP_TOKEN з .env>` — скрипт
   зробить міграції, сиди, кеші й **видалить сам себе**. Перевірити, що видалив.
4. Крон раз на хвилину (без нього не підуть Telegram-сповіщення):
   `cd ~/bur_app && php artisan queue:work --stop-when-empty --max-time=50`
5. Увімкнути Let's Encrypt: `APP_URL` уже `https://`.

Тестовий майданчик закритий від пошуковиків: `SITE_NOINDEX=true` дає `noindex`
на кожній сторінці, `robots.txt` з повним `Disallow` і 404 на `/sitemap.xml`.
На бойовому домені `SITE_NOINDEX` треба зняти — інакше сайт лишиться невидимим.

### 5.2. Запустити парсер budprokat

```bash
php artisan scrape:budprokat --limit=5 --dump   # пробний прогін
php artisan scrape:budprokat                    # повний обхід
php artisan catalog:import import/budprokat.json
```

**Важливо: селектори в `App\Services\Import\BudprokatParser` написані за
евристиками, живий HTML сайту ніхто не бачив.** Якщо перший прогін дасть
«Категорій знайдено: 0» або товари без цін — подивіться збережений HTML у
`storage/app/import/html/` і поправте селектори. Парсер покритий тестами на
фікстурах (`tests/Unit/BudprokatParserTest.php`) — правте разом із ними.

Імпортоване приходить неопублікованим: адмінка → Товари → фільтр «Чернетки з
імпорту» → перевірити ціну й категорію → «Опублікувати». Описи конкурента —
чужий контент, перед публікацією переписувати.

### 5.3. Далі за пріоритетом

1. **Оплата.** Спосіб оплати зберігається в брони, шлюзу немає. Окремо продумати
   заставу: це не платіж, а заморозка на картці (hold), і не кожен провайдер це
   вміє. Рішення про шлюз (LiqPay / Fondy / monobank) за замовником.
2. **Фото.** Скрізь плейсхолдери `<x-image-slot>` із зарезервованими
   пропорціями (вимога нульового CLS). Реальні фото від замовника.
3. Кабінет клієнта і «обране» — у хендофі є лише пунктами навігації, екранів
   немає.

## 7. Секрети

У репозиторії їх немає і бути не повинно. Передаються окремо:

- доступи до хостингу `bur.new.hor-hosting.top` (панель, БД, FTP);
- `.env` для тестового хоста — у зібраному пакеті `bur_app/.env`, там уже
  прописані база, `APP_KEY`, паролі адмінки і `SETUP_TOKEN`;
- `TELEGRAM_BOT_TOKEN` і `TELEGRAM_MANAGER_CHAT_ID` — ще не створені.

Хостингові доступи були передані в переписці, тож після успішного деплою їх
варто змінити в панелі.
